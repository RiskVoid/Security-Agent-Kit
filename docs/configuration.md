# Configuration reference

Your settings are in one file, `.env` in the kit folder. This page lists every setting, the other files you can
change, and what to run after a change.

`./rvkit setup` creates `.env` from `.env.example` with fresh secrets. It is git-ignored: never commit it or share
it. Most settings have an `./rvkit` command that changes them for you and restarts what's needed; prefer that over
editing by hand. After editing `.env` yourself, run `./rvkit up`.

## .env settings

### Folders

| Setting | Default | Meaning |
|---|---|---|
| `PROJECTS_DIR` | `~/riskvoid/projects` | Client code. Mounted read-only as `/src` in every container, so `PROJECTS_DIR/acme-repo` is `/src/acme-repo`. |
| `ENGAGEMENTS_DIR` | `~/riskvoid/engagements` | Engagement folders. Mounted as `/work` (read-only in the OpenHands container). |

`setup` asks for the parent folder. To move them later: stop the stack, move the folders, change both settings,
`./rvkit up`. Engagement names and their sandbox users live in the control volume, not in the folder, so moving the
folder keeps them working.

### Secrets

Generated by `setup`. Don't change them unless you know why.

| Setting | Used by |
|---|---|
| `LITELLM_MASTER_KEY` | Everything that calls the model gateway (OpenHands, the worker, `rvkit`). |
| `SEARXNG_SECRET` | SearXNG. |
| `COLAB_API_KEY` | The key the Colab notebook protects its endpoint with. `./rvkit key colab` prints it. |
| `OPENHANDS_API_KEY` | Lets `rvkit` configure OpenHands through its local API. |
| `REDIS_PASSWORD` | The spend counter store. Added automatically if missing. |

### Worker model

Set these with `./rvkit connect` and `./rvkit worker` ([models.md](models.md)), not by hand.

| Setting | Default | Meaning |
|---|---|---|
| `WORKER_API_BASE` | `http://worker-not-connected.invalid/v1` | OpenAI-compatible base URL of the worker endpoint. |
| `WORKER_API_KEY` | | Its API key (`none` if it has none). |
| `WORKER_MODEL_ID` | `openai/qwen38-27b-obl` | `openai/` + the model name the endpoint serves. |
| `WORKER_FALLBACK` | `off` | `on` sends worker calls to `WORKER_FALLBACK_MODEL` while the endpoint is down. |
| `WORKER_FALLBACK_MODEL` | `openrouter/deepseek/deepseek-v4.1-flash` | The fallback model (OpenRouter). |
| `COLAB_API_BASE`, `COLAB_MODEL` | | The last Colab URL and model, so `./rvkit worker colab` can switch back. |
| `WORKER_PARALLEL_TASKS` | `1` | Delegated tasks the worker runs at once. Keep 1 for Colab; raise it for an API endpoint or a local server with parallel slots. |
| `WORKER_PARALLEL_TOOLS` | `2` | Tool calls running at once across tasks (#106/#107), separate from the model: the model semaphore is held only around a model call, so a long scan doesn't block the model for everyone. |
| `WORKER_ENG_PARALLEL` | `2` | Tasks of one engagement running at once (#107) - the target's own capacity, separate from the model and tool limits. |
| `WORKER_TOOL_WAIT_S` | `120` | How long a call refused because the engagement is at its parallel limit is retried before the refusal reaches the model (#107). The refused call never ran, so the retry is safe; the wait is recorded as queue delay and not charged to the task's timeout. |
| `WORKER_ADVISOR` | `1` | A worker task that stalls (the same call or error three times, or `WORKER_STALL_CALLS` calls with nothing new) first gets a nudge, then asks the planner model for advice, at most twice, before it stops as `stalled`. Only the goal and one line per recent step are sent, through the model gateway, which applies the engagement's client data rule; a private worker never asks. `0` turns the advice off. |
| `WORKER_STALL_CALLS` | `8` | Worker calls with no new output and no candidate before a task counts as stalled. |
| `WORKER_PACKET` | `1` | The research packet (#83/#84): a worker task bound to a plan item starts from what the engagement's records already say about its coverage cell - map entries, observations and findings with their states, earlier tasks for the same cell with their typed result, the item's hypothesis and blockers - built with no model, every line keeping its state. On resume, only a material change (ids or revisions) is appended. `0` turns it off (the baseline and comparison runs). |
| `WORKER_PACKET_CHARS` | `4000` | The packet's character allowance. `evals/packet_check.py` on the labelled tuning tasks: every needed record fits by 3059 chars; a bigger budget only carries more noise (precision 0.12 at 3000, 0.08 at 6000), so the default sits just over what the labelled cells needed. |
| `RV_LEDGER` | `1` | The call ledger (#115), one setting for both sides: after a command or request runs (it always runs - a target can answer differently), the reply carries the ledger entry of an earlier equivalent call in the engagement, so the model sees what is new; a `read_file` whose file hash is unchanged and a repeated `vuln_intel` lookup are answered from the ledger with no new call (`fresh=true` runs them anyway); a stale entry is shown as stale and never reused; the task result counts notices and reuse. `0` turns it off. |
| `WORKER_ESTABLISHED_CHARS` | `2000` | The pinned 'established so far' block's allowance (#120): the task's notes, candidates and checked identities, rebuilt from the task record at every compaction; the oldest lines fall back to the task id `read_record` opens. |

| `WORKER_CONTEXT_CHARS` | `90000` | Characters of task context the worker keeps (about 25K tokens, for a 32K-context model). Raise it for a model with a longer context. Past it, the oldest tool results shrink to one line each (tool, command, exit status, digest summary, evidence path). |
| `WORKER_MAX_TOKENS` | `8192` | Output tokens per worker model call, reasoning included. With too few, a reasoning model spends the whole reply thinking and returns neither a tool call nor an answer; three such replies in a row end the task as `stalled`. |
| `WORKER_KEEP_RESULTS` | `5` | The latest tool results a worker task always keeps whole. |

### Planner model and spend

| Setting | Default | Meaning |
|---|---|---|
| `OPENROUTER_API_KEY` | empty | Your OpenRouter key. Without it only the `riskvoid-local` agent works. |
| `PLANNER_MODEL` | `openrouter/z-ai/glm-5.3` | The planner (`./rvkit planner`). |
| `PLANNER_FALLBACK_MODEL` | `openrouter/deepseek/deepseek-v4-pro` | Used when the planner call fails, refuses or returns nothing. |
| `VALIDATOR_MODEL` | the planner's fallback model | The disprove-only validator: reviews each finding the planner confirms ([tools reference](tools-reference.md#the-validator)). |
| `VALIDATOR` | `1` | `0`: confirmed findings are not sent to the validator. |
| `VALIDATOR_DISPROVE` | `flag` | What a validator disprove does. `flag`: the finding stays confirmed, the verdict is shown in the console and the report, and the report can't be delivered until the finding is corrected, withdrawn or excepted by a person. `demote`: the finding goes back to candidate. |
| `VALIDATOR_MAX_TOKENS` | `8192` | Output tokens per validator call, reasoning included. A reasoning model needs room to think and still give its verdict; with too little it returns nothing and the planner model judges the finding instead. |
| `VALIDATOR_FILE_CHARS` | `30000` | Characters of each cited evidence file the validator reads (four times that in total). A longer file is shown around the text the finding quotes, with its head and tail. |
| `REPEAT_COLLAPSE` | `1` | What the model gateway does when the planner sends the same tool call again and again. From the third in a row it leaves those turns out of what the model reads and puts one note in their place: what was called, how often and the last result. From the fourth the tool of that call is left out of the request until the planner makes a different call. At the sixth the gateway answers itself with a `[RiskVoid] Loop stopped` text and does not call the model, which ends the planner's turn. The conversation itself is unchanged. `0` turns all of it off. A cycle of two or three calls made in turn is counted the same way, in rounds. |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | empty | Only for a planner on Anthropic or OpenAI directly (`./rvkit planner --direct`). |
| `AWS_BEARER_TOKEN_BEDROCK`, `AWS_REGION_NAME` | empty | Only for models on Amazon Bedrock (`./rvkit planner --direct bedrock/...`, `./rvkit worker bedrock`): a Bedrock API key and its region. |
| `OPENROUTER_ZDR` | `on` | `off`: OpenRouter calls no longer ask for zero-data-retention providers, which OpenRouter's free models need. For benchmark runs against the lab only ([Models](models.md#free-openrouter-models-zero-retention-off)). |
| `OPENROUTER_DAILY_BUDGET` | `20` | USD per 24 hours, per provider: OpenRouter, and Anthropic / OpenAI / Bedrock when used directly (`./rvkit budget`). |

All OpenRouter calls ask for zero-data-retention providers that don't collect prompts, unless you set
`OPENROUTER_ZDR=off`. Direct Anthropic / OpenAI /
Bedrock calls follow that provider's own API data terms ([Models](models.md#anthropic-or-openai-directly)).

### Network

| Setting | Default | Meaning |
|---|---|---|
| `EGRESS_EXTRA_DOMAINS` | empty | Extra domains the OpenHands container may reach through the egress proxy, comma-separated, each with its subdomains. Example: `EGRESS_EXTRA_DOMAINS=docs.example.com,pkg.example.org`. |

This only affects the agent's own container (installing packages from its terminal). It does not change what Kali
commands can reach: that is the engagement's scope.

| Setting | Default | Meaning |
|---|---|---|
| `GATEWAY_PORT` | `8000` | Port of the UI on `127.0.0.1`. |
| `LITELLM_PORT` | `4000` | Port of the LiteLLM model gateway on `127.0.0.1`. |
| `SEARXNG_PORT` | `8888` | Port of SearXNG on `127.0.0.1`. |

Change a port when another app already uses it, then run `./rvkit up`. `rvkit` and the benchmark runner follow the
setting.

### Tracing

Off by default. `./rvkit tracing on` starts a bundled Jaeger (UI at http://127.0.0.1:16686) and exports OpenTelemetry
traces of worker tasks, model calls and tool calls to it. Jaeger sits on its own internal network with the worker and
LiteLLM, so the agent's sandbox can't read traces. Each
task is one trace: an `invoke_agent riskvoid-worker` span, with a `chat <model>` span per model call and an
`execute_tool <tool>` span per tool call. Span names and attributes follow the OpenTelemetry GenAI conventions. LiteLLM
adds a span for each model call it routes, planner calls included.

| Setting | Default | Meaning |
|---|---|---|
| `RV_TRACING` | `off` | `on` exports traces (`./rvkit tracing on` or `off`). |
| `RV_TRACE_ENDPOINT` | the bundled Jaeger | Where LiteLLM sends its model-call spans: an OTLP/HTTP endpoint, without `/v1/traces`. Langfuse takes OTLP: its `/api/public/otel` endpoint. The worker's spans always go to the bundled Jaeger, because the worker has no network route out. |
| `RV_TRACE_HEADERS` | empty | Headers for `RV_TRACE_ENDPOINT`, as `Name=value,Name2=value2`. Langfuse: `Authorization=Basic <base64 of public-key:secret-key>`. Set it in `.env` yourself; it is a secret. |
| `RV_TRACE_CONTENT` | `off` | `on` puts content into the worker's spans: messages, tool arguments and tool results (`./rvkit tracing content on` or `off`). |
| `RV_TRACE_DESTINATION` | `local` | The name the trace collector has in an engagement's Client data rule. |

Without content, spans carry names, timings, models, token counts, tool names and statuses: no client code, no tool
output. With `RV_TRACE_CONTENT=on`, content goes into a task's spans only when its engagement's **Client data** rule
allows `RV_TRACE_DESTINATION` (or has no Client data rule) and its **Network** rule isn't `offline`. LiteLLM's own
spans never carry messages, because LiteLLM can't apply that rule per engagement. A collector outside your machine is
a place client data goes: name it in `RV_TRACE_DESTINATION`, and allow it only in the engagements that may send data
there.

## Other files you can change

| File | What it controls | After changing |
|---|---|---|
| `egress/allowlist.txt` | Domains the OpenHands container may reach (package registries, vulnerability databases). Prefer `EGRESS_EXTRA_DOMAINS` for your own additions. | `RVKIT_BUILD=1 ./rvkit up` (the list is built into the image) |
| `kali-mcp/infra_domains.txt` | Domains every **online** engagement's Kali commands may reach on ports 80/443 (rule packs, registries, vulnerability databases). | `RVKIT_BUILD=1 ./rvkit up` |
| `prompts/planner.md`, `prompts/local.md` | The agents' instructions. `{{ORG_NAME}}` is replaced with your organisation. | `./rvkit openhands`, then start a new conversation |
| `harness/playbooks/*.md` | Methodology playbooks ([tools-reference.md](tools-reference.md#playbooks)). | `RVKIT_BUILD=1 ./rvkit up` |
| `litellm/config.yaml` | Model routing template. `rvkit` renders it with your `.env` into `.rvkit/litellm.yaml`, which LiteLLM reads. Don't edit the generated file. | `./rvkit up` |
| `docker-compose.yml` | Services, versions. Ports are set in `.env` ([operations.md](operations.md#ports)). | `./rvkit up` |
| Engagement `SCOPE.md` / `RULES.md` | Scope and rules of one engagement ([engagements.md](engagements.md)). | `./rvkit scope <engagement> --yes` |

To override the infrastructure domains for one install without rebuilding, put your own list in the control volume
and re-apply the firewall:

```sh
docker compose cp my_infra_domains.txt kali-mcp:/control/infra_domains.txt
docker compose exec kali-mcp python3 /opt/kali-mcp/rvctl.py apply
```

## Generated and local state

| Path | What it is |
|---|---|
| `.env` | Your settings and secrets. |
| `.rvkit/litellm.yaml` | LiteLLM config rendered from the template and `.env`. Regenerated by every command that touches models. |
| `evals/results/` | Benchmark and smoke-test results. Git-ignored: they can contain model output about your targets. |

Docker volumes (kept by `./rvkit down`): see [operations.md](operations.md#data-and-backups).

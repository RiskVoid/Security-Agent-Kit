# Configuration reference

Your settings are in one file, `.env` in the kit folder. This page lists every setting, the other files you can
change, and what to run after a change.

`./rvkit setup` creates `.env` from `.env.example` with fresh secrets. It is git-ignored: never commit it or share
it. Most settings have an `./rvkit` command that changes them for you and restarts what's needed; prefer that over
editing by hand. After editing `.env` yourself, run `./rvkit up`.

## .env settings

### Folders

| Setting | Default | Meaning |
|---|---|---|
| `PROJECTS_DIR` | `~/riskvoid/projects` | Client code. Mounted read-only as `/src` in every container, so `PROJECTS_DIR/acme-repo` is `/src/acme-repo`. |
| `ENGAGEMENTS_DIR` | `~/riskvoid/engagements` | Engagement folders. Mounted as `/work` (read-only in the OpenHands container). |

`setup` asks for the parent folder. To move them later: stop the stack, move the folders, change both settings,
`./rvkit up`. Engagement names and their sandbox users live in the control volume, not in the folder, so moving the
folder keeps them working.

### Secrets

Generated by `setup`. Don't change them unless you know why.

| Setting | Used by |
|---|---|
| `LITELLM_MASTER_KEY` | Everything that calls the model gateway (OpenHands, the worker, `rvkit`). |
| `SEARXNG_SECRET` | SearXNG. |
| `COLAB_API_KEY` | The key the Colab notebook protects its endpoint with. `./rvkit key colab` prints it. |
| `OPENHANDS_API_KEY` | Lets `rvkit` configure OpenHands through its local API. |
| `REDIS_PASSWORD` | The spend counter store. Added automatically if missing. |

### Worker model

Set these with `./rvkit connect` and `./rvkit worker` ([models.md](models.md)), not by hand.

| Setting | Default | Meaning |
|---|---|---|
| `WORKER_API_BASE` | `http://worker-not-connected.invalid/v1` | OpenAI-compatible base URL of the worker endpoint. |
| `WORKER_API_KEY` | | Its API key (`none` if it has none). |
| `WORKER_MODEL_ID` | `openai/qwen38-27b` | `openai/` + the model name the endpoint serves. |
| `WORKER_FALLBACK` | `off` | `on` sends worker calls to `WORKER_FALLBACK_MODEL` while the endpoint is down. |
| `WORKER_FALLBACK_MODEL` | `openrouter/deepseek/deepseek-v4.1-flash` | The fallback model (OpenRouter). |
| `COLAB_API_BASE`, `COLAB_MODEL` | | The last Colab URL and model, so `./rvkit worker colab` can switch back. |
| `WORKER_PARALLEL_TASKS` | `1` | Delegated tasks the worker runs at once. Keep 1 for Colab; raise it for an API endpoint or a local server with parallel slots. |
| `WORKER_CONTEXT_CHARS` | `90000` | Characters of task context the worker keeps (about 25K tokens, for a 32K-context model). Raise it for a model with a longer context. |

### Planner model and spend

| Setting | Default | Meaning |
|---|---|---|
| `OPENROUTER_API_KEY` | empty | Your OpenRouter key. Without it only the `riskvoid-local` agent works. |
| `PLANNER_MODEL` | `openrouter/anthropic/claude-sonnet-5.5` | The planner (`./rvkit planner`). |
| `PLANNER_FALLBACK_MODEL` | `openrouter/openai/gpt-6.1-sol` | Used when the planner call fails. |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | empty | Only for a planner on Anthropic or OpenAI directly (`./rvkit planner --direct`). |
| `OPENROUTER_DAILY_BUDGET` | `20` | USD per 24 hours, per provider: OpenRouter, and Anthropic / OpenAI when used directly (`./rvkit budget`). |

All OpenRouter calls ask for zero-data-retention providers that don't collect prompts. Direct Anthropic / OpenAI
calls follow that provider's own API data terms ([Models](models.md#anthropic-or-openai-directly)).

### Reports and branding

| Setting | Default | Meaning |
|---|---|---|
| `REPORT_BRAND` | `riskvoid` | `riskvoid`, `plain` (neutral, no logo) or `custom`. |
| `ORG_NAME` | empty | Your organisation: on the report, and in the planner's instructions ("lead security consultant for …"). Empty means RiskVoid for the `riskvoid` brand, "the security team" otherwise. |
| `REPORT_BRAND_FOLDER` | `./harness/brands/example` | Your brand folder, used when `REPORT_BRAND=custom`. See [harness/brands/example/README.md](../harness/brands/example/README.md). |

Run `./rvkit up` after changing them. Details: [findings-and-reports.md](findings-and-reports.md).

### Network

| Setting | Default | Meaning |
|---|---|---|
| `EGRESS_EXTRA_DOMAINS` | empty | Extra domains the OpenHands container may reach through the egress proxy, comma-separated, each with its subdomains. Example: `EGRESS_EXTRA_DOMAINS=docs.example.com,pkg.example.org`. |

This only affects the agent's own container (installing packages from its terminal). It does not change what Kali
commands can reach: that is the engagement's scope.

| Setting | Default | Meaning |
|---|---|---|
| `GATEWAY_PORT` | `8000` | Port of the UI on `127.0.0.1`. |
| `LITELLM_PORT` | `4000` | Port of the LiteLLM model gateway on `127.0.0.1`. |
| `SEARXNG_PORT` | `8888` | Port of SearXNG on `127.0.0.1`. |

Change a port when another app already uses it, then run `./rvkit up`. `rvkit` and the benchmark runner follow the
setting.

### Optional

| Setting | Default | Meaning |
|---|---|---|
| `NVD_API_KEY` | empty | Raises NVD's rate limit for CVE lookups (5 to 50 requests per 30 s). Free from https://nvd.nist.gov/developers/request-an-api-key. |
| `AGENT_CANVAS_TAG` | `1.33.0` (in `docker-compose.yml`) | OpenHands version. Change it only to test a newer release, or when its data volume was already used by a newer version. |
| `LITELLM_TAG`, `SEARXNG_TAG`, `CADDY_TAG`, `VALKEY_TAG` | pinned in `docker-compose.yml` | Override a third-party image version. |
| `RVKIT_REGISTRY` | `ghcr.io/riskvoid/security-agent-kit` | Where the kit's own images are pulled from (`-egress`, `-harness`, `-kali`, `-report`). |
| `RVKIT_VERSION` | `0.1.0` | Which published version of the kit's images to pull. Normally matches the `VERSION` file. |
| `SEMGREP_RULES_COMMIT` | pinned in `docker-compose.yml` | Commit of the Semgrep community rules downloaded into the `semgrep-rules` volume on first start. |

## Other files you can change

| File | What it controls | After changing |
|---|---|---|
| `egress/allowlist.txt` | Domains the OpenHands container may reach (package registries, vulnerability databases). Prefer `EGRESS_EXTRA_DOMAINS` for your own additions. | `RVKIT_BUILD=1 ./rvkit up` (the list is built into the image) |
| `kali-mcp/infra_domains.txt` | Domains every **online** engagement's Kali commands may reach on ports 80/443 (rule packs, registries, vulnerability databases). | `RVKIT_BUILD=1 ./rvkit up` |
| `prompts/planner.md`, `prompts/local.md` | The agents' instructions. `{{ORG_NAME}}` is replaced with your organisation. | `./rvkit openhands`, then start a new conversation |
| `harness/playbooks/*.md` | Methodology playbooks ([tools-reference.md](tools-reference.md#playbooks)). | `RVKIT_BUILD=1 ./rvkit up` |
| `litellm/config.yaml` | Model routing template. `rvkit` renders it with your `.env` into `.rvkit/litellm.yaml`, which LiteLLM reads. Don't edit the generated file. | `./rvkit up` |
| `docker-compose.yml` | Services, versions. Ports are set in `.env` ([operations.md](operations.md#ports)). | `./rvkit up` |
| Engagement `SCOPE.md` / `RULES.md` | Scope and rules of one engagement ([engagements.md](engagements.md)). | `./rvkit scope <engagement> --yes` |

To override the infrastructure domains for one install without rebuilding, put your own list in the control volume
and re-apply the firewall:

```sh
docker compose cp my_infra_domains.txt kali-mcp:/control/infra_domains.txt
docker compose exec kali-mcp python3 /opt/kali-mcp/rvctl.py apply
```

## Generated and local state

| Path | What it is |
|---|---|
| `.env` | Your settings and secrets. |
| `.rvkit/litellm.yaml` | LiteLLM config rendered from the template and `.env`. Regenerated by every command that touches models. |
| `evals/results/` | Benchmark and smoke-test results. Git-ignored: they can contain model output about your targets. |

Docker volumes (kept by `./rvkit down`): see [operations.md](operations.md#data-and-backups).
